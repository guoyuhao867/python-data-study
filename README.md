# python-data-study

面向工业设备故障诊断的学习与实践仓库，从 Python 数据分析逐步推进到机器学习、深度学习、信号处理、模型部署与知识增强 LLM。

主线项目：读取振动数据 → 清洗与可视化 → 提取特征 → 建立诊断模型 → 部署接口 → 结合专业资料解释结果。

## 学习计划

| 方向 | 学习内容 | 达成目标 | 优先级 |
| --- | --- | --- | --- |
| 编程与工程基础 | Python、NumPy、Pandas、Matplotlib、SQL、Git、Linux | 能独立读取数据、清洗分析、调试程序和管理项目 | 必须 |
| 数学与统计 | 线性代数、概率统计、导数与梯度、常见优化方法 | 理解模型输入输出、损失函数、参数更新与评价指标 | 必须 |
| 机器学习 | scikit-learn、SVM、随机森林、梯度提升树、特征工程 | 能建立基线模型，完成调参、对比与错误分析 | 必须 |
| 深度学习 | PyTorch、Dataset/DataLoader、CNN、训练与验证流程 | 能独立训练模型，保存权重，处理过拟合并复现实验 | 必须 |
| 工业信号处理 | SciPy、滤波、FFT、包络谱、时域与频域特征 | 理解振动数据与设备故障之间的联系 | 主攻方向 |
| 模型部署 | Flask 或 FastAPI、Docker、日志、模型版本管理 | 能将模型封装为接口，验证延迟与稳定性 | 必须 |
| 知识增强 LLM | 文档处理、Embedding、RAG、引用溯源、结构化输出 | 能根据专业资料解释诊断结果，并评价回答质量 | 与课题结合 |
| 推理优化 | ONNX、量化、GPU 推理基础 | 能根据实际性能瓶颈开展优化 | 后续加分 |

## 推荐推进顺序与验收

数学与统计穿插各阶段学习；工业信号处理从数据分析阶段开始接触，再逐步深入。

- [ ] **阶段 1：编程与数据分析。** 读取一份 CSV，处理缺失值与重复值，完成分组统计和图表；用 SQLite 查询数据，用 Git 保存练习，并熟悉 Linux 文件、进程与环境命令。
- [ ] **阶段 2：数学与信号处理。** 理解采样率、奈奎斯特频率与频谱泄漏；完成时域波形、FFT、滤波、包络谱和 RMS、峭度等特征提取。结合概率统计理解噪声与特征分布。
- [ ] **阶段 3：机器学习诊断基线。** 使用 scikit-learn Pipeline 完成特征处理，对比 SVM、随机森林和梯度提升树，记录调参过程、混淆矩阵、各类别指标与错误案例。
- [ ] **阶段 4：深度学习。** 用 PyTorch Dataset/DataLoader 和一维 CNN 建立训练、验证、测试流程；保存最优权重，记录随机种子、环境、配置与训练曲线，并与传统模型比较。
- [ ] **阶段 5：模型部署。** 选择 FastAPI 或 Flask，将预处理和模型一起封装为接口；增加输入校验、日志、模型版本与 Docker 环境，测量延迟和异常输入表现。
- [ ] **阶段 6：知识增强解释。** 基于专业文档建立 RAG，输出含引用的诊断解释，并用固定问题集评价检索、引用准确性、回答质量和证据不足时的表现。
- [ ] **阶段 7：推理优化。** 先测量预处理、模型与接口耗时，再按实际瓶颈选择 ONNX、量化或 GPU，并验证优化后的精度与性能。

## 实验约定

- 数据按设备、采集批次或时间划分训练、验证和测试集；同一段原始信号切出的相邻窗口不能跨集合，避免数据泄漏。
- 标准化、特征选择等只在训练集拟合；测试集用于最终评估，不参与调参。
- 每次实验记录数据来源与划分、代码版本、参数、指标和结论；保留可复现的基线。
- LLM 解释应有专业资料支持，不把生成内容当作故障事实；证据不足时明确说明。
- 公开仓库只提交可公开的代码和资料。真实工业数据须确认授权，密钥通过环境变量管理。

## 准备环境

需要 Python 3。在项目目录执行：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python main.py
```

Windows 激活命令：`.venv\Scripts\activate`。

SQLite 可通过 Python 标准库 `sqlite3` 使用，无需额外安装 Python 包。
